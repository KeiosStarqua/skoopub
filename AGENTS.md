# AGENTS.md

Index of this repository for agents and humans. **skoop** is a declarative Windows
dev setup: [Scoop](https://scoop.sh) packages plus a repo-managed PowerShell profile,
restored from one manifest. There is no build system, no tests, and no package
manager of its own — the files are the product.

## Conventions

### Repository organization rules

- **Architecture:** feature-based, application-centric directories. `apps/<application>/` holds that application's scripts, configs, templates and fixes; `core/` holds shared orchestration; `shell/` the shared PowerShell profile; `manifests/` package manifests; future `tests/` and `docs/` folders are optional.
- **Root directory:** keep it minimal -- public entry points (`install.ps1`, `bootstrap.ps1`), documentation and metadata only. No application-specific scripts or configs in the root.
- **Application isolation:** every managed app owns a directory under `apps/`. All app-specific files live there; do not create global `configs/`, `fixes/` or `scripts/` folders.
- **Naming:** lowercase kebab-case for files/directories. Do not repeat the application name in a filename when the parent directory already identifies it. Use standard names (`configure.ps1`, `setup.ps1`, `install.ps1`, `uninstall.ps1`, `update.ps1`, `verify.ps1`, `enable-autostart.ps1`, `fix-<issue>.ps1`, `*.template.json`), preserving names required by third-party apps.
- **Script design:** scripts must be idempotent and independent of the current working directory; resolve repo-relative paths from `$PSScriptRoot` plus `Join-Path`. Keep app logic inside its app directory; extract genuinely shared logic into `core/`. Root `install.ps1` is the public entry point and delegates app-specific work.
- **When moving or renaming:** use `git mv`; update all script references and relative paths; update README.md/AGENTS.md and both bootstraps; preserve command-line arguments and public behaviour; verify no references to old paths remain; test the affected installation/configuration flows before finishing.
- Do not add unnecessary directories, empty placeholder scripts or abstractions without a concrete requirement.
- **Add or remove a package** by editing `manifests/scoop.json`; keep the `{ "Info": "", "Source": ..., "Name": ... }` shape and keep apps grouped by source. Real-world workflow: `scoop install <app>` then `scoop export | Out-File -Encoding utf8 manifests/scoop.json` (verify the diff before committing). Every app must also appear in exactly one phase in `manifests/phases.json`; `core/scoop-phases.ps1` throws when an app is unassigned, duplicated or unknown, so a forgotten phase fails loudly instead of being skipped.
- **Re-runs skip installed apps:** `core/scoop-phases.ps1` exposes `Get-SkoopInstalledApps` (checks `apps\<name>\current` under `$SCOOP`, `~/scoop` or ProgramData, so no locale-dependent `scoop list` parsing) and `Invoke-SkoopPhases -SkipInstalled` removes those apps from each generated phase manifest; a phase with no pending apps is not imported at all (but its `-AfterPhase` callback still runs). Both bootstraps pass `-SkipInstalled`; `-ForceInstall` / `-Force` / `$env:SKOOP_FORCE_INSTALL=1` defeats the check for Scoop apps only and is forwarded through `Get-SkoopReLaunchArgs`. An explicit `-ExcludeApps` (e.g. the deliberate UniKey skip) is never overridden by `-Force`. Keep the option, the help text and README's "Updating this machine later" section in sync.
- **Phased install:** `manifests/scoop.json` stays the source of truth for versions; `manifests/phases.json` only maps app names to ordered phases. `core/scoop-phases.ps1` validates the mapping, generates one temporary `{ buckets, apps }` manifest per phase (only the buckets that phase needs) and runs `scoop import` in order. Phase 1 (`core-terminal`: git, pwsh, rio, herdr, herdr-core, vicinae, JetBrainsMono-NF, JetBrainsMono-NF-Propo, tailscale) is the fast essentials: Rio is deliberately installed before Herdr, and `install.ps1` finishes Rio/Vicinae/Herdr setup, starts Tailscale and runs `tailscale up --qr` for sign-in, then re-launches under pwsh immediately after it; `-EssentialsOnly` stops there. Later phase failures are reported and skipped so a slow download cannot take the essentials down; phase 1 failures are fatal.
- **Buckets must exist before their apps**; if you introduce a new bucket, add it to `buckets`, list it on the phase(s) that need it, and make sure `install.ps1`/`bootstrap.ps1` still import cleanly (buckets are git repos, hence the git step).
- The `kbots` app builds from a pinned source commit (no deploy tag needed); `bun`, `rustup`, `mingw` and `git` are already in `manifests/scoop.json`. Its install does not start the daemon — run `kbots daemon start` after setup.
- Ollama is installed as `extras/ollama-full` in the `apps` phase (extra bucket already listed there). Do **not** swap it for `main/ollama`: that manifest is CLI-only and its note says the daemon moved to `ollama-full`, so `ollama run` would have no server. Models are never pulled by the bootstrap (multi-GB); users pull them themselves. No `apps/ollama/` directory is needed — Scoop supplies the `ollama` shim. Keep the README Ollama row in sync.
- Tailnet tagging: both bootstraps call `apps/tailscale/configure.ps1` after starting Tailscale. It advertises `tag:public-client` on the current device only when connected and the tag is not already advertised; failures are non-fatal. The tailnet ACL must allow the user to own that tag. `-SkipTag` opts out when the script is run directly. `-SignIn` runs `tailscale up --qr` first when the node is not connected, which is how the `core-terminal` phase gets the login URL/QR on screen before Firefox is installed. The `core-terminal` call also passes `-RestoreVicinae` and `-RestorePearDesktop`: once a fresh `status --json` probe confirms `BackendState=Running` and `Self.Online`, the script invokes `core/restore-backup.ps1 -Only vicinae` / `-Only pear` (using `-BackupUser` / `SKOOP_BACKUP_USER`) and writes `%LOCALAPPDATA%\skoop\vicinae-restore-on-connect.done` / `pear-restore-on-connect.done` so re-runs skip the download. `-ForceVicinaeRestore` / `-ForcePearDesktopRestore` repeat one app; restore failures are non-fatal and never block install or tagging. OpenCode is restored with `-RestoreOpenCode` after the app phases (its CLI must exist for `opencode auth import`) and uses the marker `%LOCALAPPDATA%\skoop\opencode-restore.done`; `-ForceOpenCodeRestore` repeats it. The same `core-terminal` call also passes `-RestoreFirefox -RestoreAtuin`: Firefox's profile and Atuin's config/history are restored as soon as Tailscale connects/up, with markers `%LOCALAPPDATA%\skoop\firefox-restore.done` / `atuin-restore.done`. Both apps are installed in later phases, so this only lays down files (no CLI dependency, unlike OpenCode); Firefox is closed/relaunched around the copy and Atuin warns to close other shells. `install.ps1` retries both at the end of the run as an idempotent fallback (the markers make the early call a no-op on re-runs); `core/bootstrap.ps1` does the same in its step 6. Both bootstraps expose `-ForceFirefoxRestore` / `-ForceAtuinRestore` (env `SKOOP_FORCE_FIREFOX_RESTORE=1` / `SKOOP_FORCE_ATUIN_RESTORE=1`) to repeat one and `-SkipFirefoxRestore` / `-SkipAtuinRestore` (env `SKOOP_NO_FIREFOX_RESTORE=1` / `SKOOP_NO_ATUIN_RESTORE=1`) to opt out; the skip switches are forwarded by `Get-SkoopReLaunchArgs`. All failures are non-fatal. In `install.ps1` this restore call runs at the **start** of `Invoke-EssentialTerminalSetup`, before `apps/vicinae/configure.ps1` and `apps/vicinae/enable-autostart.ps1`, so the Vicinae database/config/state from the snapshot is restored before the app is configured or launched and the repo-managed keybinds are written on top. Piped installs must fetch `core/restore-backup.ps1` alongside `apps/tailscale/configure.ps1`.
- **Scripts target Windows PowerShell 5.1+** with `$ErrorActionPreference = 'Stop'`, and must run without admin unless explicitly elevated. Avoid PowerShell 7-only syntax.
- **Idempotence matters.** `install.ps1`/`bootstrap.ps1` and `shell/profile.ps1` may run repeatedly; check before appending to `$PROFILE` and guard optional commands with `Get-Command ... -ErrorAction SilentlyContinue`.
- **Default mode is Full, not a menu.** A bare `.\install.ps1` (or piped `irm ... | iex`) must run the full setup without asking which mode to use. The gum/numbered selector is opt-in via `-Menu` / `SKOOP_MENU=1`; `-NoMenu` stays as a no-op and `SKOOP_NO_MENU=1` overrides `-Menu`. Forward `-Menu` through `Get-SkoopReLaunchArgs` (except when re-launching with `-SkipMenu`) so a chosen mode survives the pwsh re-launch.
- **Local checkouts live in `~/repos`.** Both bootstraps call `Ensure-SkoopClone` after git is available: it creates `%USERPROFILE%\repos` and clones `KeiosStarqua/skoopub` into `~/repos\skoopub` when that folder is missing (the clone URL is derived from `-RepoRawBase`, so forks work). An existing directory or checkout is never touched, and a failed clone is non-fatal. Piped installs keep using the files fetched to `%LOCALAPPDATA%\skoop` for that run; subsequent runs can use the local checkout. `manifests/repos.json` extends this to the other registered checkouts: `install.ps1` calls `Ensure-RegisteredRepos` right after `Ensure-SkoopClone`, cloning entries with a URL (`git clone -b <branch> <url> ~/repos/<name>`) and skipping entries without an origin, existing `.git` checkouts, and non-git directories that already occupy the target. Failures are non-fatal; `-SkipRepoClones` / `SKOOP_NO_REPO_CLONES=1` opts out and is forwarded by `Get-SkoopReLaunchArgs`. Register a new machine's repo by adding `{ name, url, branch }` to the manifest (and fetch it in the piped list).
- **Rio first, then Herdr, and Herdr is opened for you.** Phase 1 installs `rio` before `herdr`/`herdr-core`; after the essentials setup both bootstraps call `Start-HerdrInRio`, which opens `rio -w <~/repos> -e pwsh -NoLogo -NoExit -Command herdr`. It skips non-interactive shells, Herdr panes (`HERDR_ENV=1`) and `-NoAutoHerdr` / `SKOOP_NO_AUTO_HERDR=1`, and clears all six `HERDR_*` markers before `Start-Process` so the child is not mistaken for a nested session. Keep this opt-out switch in `Get-SkoopReLaunchArgs` and the help/docs.
- **Hook both profile editions:** PowerShell 5.1 (`Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`) and 7+ (`Documents\PowerShell\Microsoft.PowerShell_profile.ps1`) use separate files, and `install.ps1` re-launches into pwsh. `Get-ProfileTargets` returns the current `$PROFILE` plus the other edition's path (via `[Environment]::GetFolderPath('MyDocuments')`, so OneDrive redirection is respected), and `Install-ProfileHook` rewrites the dot-source line in each. Stale-hook detection matches the installer's marker comment plus the dot-source line after it (and any dot-source under the repo root), so an old path such as the pre-refactor `<repo>\profile.ps1` is replaced even when the repo folder is renamed. Compare hook text with `\r\n` normalised to `\n`, otherwise 5.1 and 7 rewrite each other's file on every run.
- **Interactive Herdr peer choice:** `.\install.ps1 -HerdrPeer` is a switch (no value) and always opens the gum peer picker; `-Peer <ip|name>` skips it, `-HerdrUser` presets the SSH user. Never commit a machine name or tailnet IP into tracked files — pass them at runtime (arguments or `SKOOP_HERDR_PEER` / `SKOOP_HERDR_USER` env vars for piped runs).
- **gum pickers:** gum draws its UI on **stderr** and writes only the answer to **stdout**. Do not capture it with `... 2>&1 | Out-String` (no terminal → gum draws nothing and returns no choice) and do not simply let PowerShell inherit stderr (PS 5.1 raises a terminating `NativeCommandError` for every UI frame under `$ErrorActionPreference='Stop'`). `Invoke-GumPicker` in `install.ps1` / `apps/herdr/setup-ssh.ps1` starts gum via `System.Diagnostics.ProcessStartInfo` with `RedirectStandardOutput = $true` and `RedirectStandardError = $false`, then reads the answer from `StandardOutput`. `-NoGum` / `$env:SKOOP_NO_GUM=1` still forces the numbered prompt when a terminal cannot render gum at all.
- **Execution policy:** `Set-SkoopExecutionPolicy` in both `install.ps1` and `core/bootstrap.ps1` sets `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` before `Install-ProfileHook`, so the dot-sourced profile loads in new shells (Rio included) instead of erroring with *"running scripts is disabled on this system"*. It skips when CurrentUser is already `RemoteSigned`/`Unrestricted`/`Bypass` and reports failures non-fatally (Group Policy can lock the scope). After `Install-ProfileHook`, `Test-SkoopProfileLoads` in both bootstraps spawns a fresh `powershell.exe` **with** its profile and checks for `Clear-HerdrEnv` from `shell/profile.ps1`, catching a Restricted policy or a stale hook; a failure is printed in red but is non-fatal. Keep both copies in sync with the install section of `README.md`.
- **PowerShell 7 preference:** `install.ps1` re-launches itself with `pwsh -NoProfile -File <script> <same args>` when it is running under Windows PowerShell 5.1 and `pwsh` is already on PATH, because 5.1 mangles native stderr and BOM-less UTF-8. It checks again right after phase 1 installs `pwsh`, so the rest of the run (phases 2-4 and every configure step) already executes under 7; that second launch adds `-NoMenu` (harmless now that the menu is opt-in via `-Menu`) and inherits `SKOOP_PWSH_RELAUNCHED=1` so it cannot loop. `-NoPwsh` / `$env:SKOOP_NO_PWSH=1` opts out; piped `irm ... | iex` runs (no `$PSCommandPath`) and `bootstrap.ps1` keep running in the invoking shell. Keep scripts 5.1-compatible — the re-launch is an optimisation, not a requirement.
- **Keep the three docs in sync** when behavior changes: `README.md` (users), `AGENTS.md` (inventory/conventions), and the comment-based help in `install.ps1`.
- **Verify changes** with `scoop export` (manifest fidelity) and by re-running the affected script in a fresh `powershell` process; there is no automated test suite.
- **Dark mode:** `core/set-dark-mode.ps1` is the single place for the OS theme: it reads `AppsUseLightTheme` / `SystemUsesLightTheme` under HKCU `...\Themes\Personalize`, sets both to `0` only when either is light, and best-effort broadcasts `ImmersiveColorSet`. Both bootstraps call it near the end (non-fatal), and piped installs fetch it alongside `core/scoop-phases.ps1`; keep those three references in sync when editing it.
- **ShareX PrtSc fix is check-first:** `apps/sharex/fix-printscreen.ps1` reads `HKCU:\Control Panel\Keyboard\PrintScreenKeyForSnippingEnabled` (requires a DWORD `0`) and checks whether `ApplicationConfig.json` / `HotkeysConfig.json` already exist before writing anything. When everything is already correct it prints `already applied - no changes needed` and returns - no registry rewrite and no ShareX restart, so repeated bootstrap runs stop re-applying it. `-Force` is the explicit re-apply/restart escape hatch, `-RestartExplorer` still forces an Explorer restart and `-NoRestart` skips the ShareX restart. Both bootstraps call it (install.ps1 step label `Checking ShareX PrtSc fix`, core/bootstrap.ps1 step 9); keep the install.ps1 comment-based help bullet and README step 10 in sync.
- **Logitech hardware DPI:** `apps/mouse/src/dpi.rs` uses `hidapi` (hidapi-rs) and the HID++ 2.0 Adjustable DPI feature `0x2201` — protocol from libratbag's `hidpp20.c`. On Windows the Logitech vendor collection (usage page `0xff00`) has an interrupt-OUT interface (usage `0x01`) for requests and an interrupt-IN one (usage `0x02`) for replies; a short HID++ request is `[0x10, 0xff, feature, func|0x08, p0, p1, p2]` and replies may use report `0x11`, so match on feature/function when reading. It reads the range/current DPI, writes the target, and reads back to verify; it is idempotent and `-DryRun` only reports. `mouse.ps1 dpi -Dpi <n>` (default 1200) and `skoopub-mouse dpi [--value n]` expose it; `install.ps1` calls it after `apps/mouse/configure.ps1` with `-MouseDpi` / `SKOOP_MOUSE_DPI` and `-SkipMouseDpi` / `SKOOP_NO_MOUSE_DPI=1`, forwarded through `Get-SkoopReLaunchArgs`. Failures are non-fatal, G H UB may stay running, and no G H UB config file, driver or registry value is edited. Keep `Cargo.lock`, the CLI help, README and AGENTS in sync; build with the GNU toolchain as `apps/mouse/configure.ps1 -Build` does.
- **LibreScroll:** `apps/librescoll/configure.ps1` installs the latest `LibreScroll/LibreScroll` release on every `install.ps1` run (non-fatal): it requires the GitHub API `sha256:` digest, extracts to `%LOCALAPPDATA%\skoop\librescoll\<tag>`, writes `LibreScroll.lnk` to the per-user Startup folder and starts the tray app when it is not running. The app is a portable, unsigned, GPL-3.0 Zig binary; `-Force` re-downloads, `-NoLaunch` / `-NoAutostart` opt out when run directly. Its `WH_MOUSE_LL` hook blocks physical `WM_MOUSEWHEEL`/`WM_MOUSEHWHEEL` while active, so the README's mouse diagnostics section must keep telling users to pause it before `skoopub-mouse diagnose`. `apps/drag-scroll/` is kept in the repo (AHK v2 drag-scroll experiment) but `install.ps1` no longer calls it; keep the two distinct so a future switch is explicit.
- **Mouse diagnostics:** diagnostics come before correction. `.github/workflows/mouse-release.yml` builds the Rust exe on `mouse-v*` tags; `apps/mouse/configure.ps1` downloads that asset and `apps/mouse/mouse.ps1` is the CLI. `diagnose` supports `--expect down@0-25,up@30-55` to check events against the operator's intended direction, and flags injected input (`LLMHF_INJECTED`) plus unresolved HID paths so a synthetic sample can never be mistaken for a physical-mouse fault. `diagnose` also separates per-direction errors (`expected_down_*` / `expected_up_*`), counts `outside_expect_events` during rest windows, and uses `-Cues` beeps for the 60 s protocol. `mouse.ps1 driver` is a read-only PowerShell inspection (`inspect`/`stack`/`filters`/`integrity`/`events`/`report`) of the PnP device, INF/version/service, parent chain, Mouse/HID/USB class filters, Authenticode signatures and Kernel-PnP/USB events; it changes nothing. `fix` installs a `WH_MOUSE_LL` hook and only enables inversion when `diagnose` shows >= 5 mismatches and >= 60% mismatch; `restore` stops it. Do not auto-toggle registry, drivers or cafe-management software from this module, and keep the security note in `apps/mouse/README.md` (public PCs with broken activation/update/Defender) accurate.
- **Editor config:** keep Zed user config in `apps/zed/` and re-run `.\apps\zed\configure.ps1` after edits. Never put credentials, API keys or tokens in these public JSON files.
- **UniKey auto config:** `apps/unikey/configure.ps1` is called by both bootstraps after the apps phase (non-fatally, with `-Force:$ForceUniKey`). UniKey 4.6 RC2 from the `zeldrisho` bucket stores settings at `HKCU:\SOFTWARE\PkLong\UniKey`, **not** `HKCU:\Software\UniKey` — only mirror into the legacy path when it already exists. ## Git workflow

- **Auto commit and push.** After finishing a change, commit and push it to `origin`
  without waiting to be asked. Stage only the files you touched (`git add <paths>`),
  write a concise imperative message (e.g. `Add one-shot install script and README`),
  then `git push`. Don't sweep unrelated work-in-progress into the commit; if the push
  is rejected, `git pull --rebase` and retry once.
- Skip the commit/push only when the user explicitly asks you not to, or when the change
  is unverified and the user wants to review it first.
