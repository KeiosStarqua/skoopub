# AGENTS.md

Index of this repository for agents and humans. **skoop** is a declarative Windows
dev setup: [Scoop](https://scoop.sh) packages plus a repo-managed PowerShell profile,
restored from one manifest. There is no build system, no tests, and no package
manager of its own — the files are the product.

## Conventions

### Repository organization rules

- **Architecture:** feature-based, application-centric directories. `apps/<application>/` holds that application's scripts, configs, templates and fixes; `core/` holds shared orchestration; `shell/` the shared PowerShell profile; `manifests/` package manifests; future `tests/` and `docs/` folders are optional.
- **Root directory:** keep it minimal -- public entry points (`install.ps1`, `bootstrap.ps1`), documentation and metadata only. No application-specific scripts or configs in the root.
- **Application isolation:** every managed app owns a directory under `apps/`. All app-specific files live there; do not create global `configs/`, `fixes/` or `scripts/` folders.
- **Naming:** lowercase kebab-case for files/directories. Do not repeat the application name in a filename when the parent directory already identifies it. Use standard names (`configure.ps1`, `setup.ps1`, `install.ps1`, `uninstall.ps1`, `update.ps1`, `verify.ps1`, `enable-autostart.ps1`, `fix-<issue>.ps1`, `*.template.json`), preserving names required by third-party apps.
- **Script design:** scripts must be idempotent and independent of the current working directory; resolve repo-relative paths from `$PSScriptRoot` plus `Join-Path`. Keep app logic inside its app directory; extract genuinely shared logic into `core/`. Root `install.ps1` is the public entry point and delegates app-specific work.
- **When moving or renaming:** use `git mv`; update all script references and relative paths; update README.md/AGENTS.md and both bootstraps; preserve command-line arguments and public behaviour; verify no references to old paths remain; test the affected installation/configuration flows before finishing.
- Do not add unnecessary directories, empty placeholder scripts or abstractions without a concrete requirement.
- **Add or remove a package** by editing `manifests/scoop.json`; keep the `{ "Info": "", "Source": ..., "Name": ... }` shape and keep apps grouped by source. Real-world workflow: `scoop install <app>` then `scoop export | Out-File -Encoding utf8 manifests/scoop.json` (verify the diff before committing). Every app must also appear in exactly one phase in `manifests/phases.json`; `core/scoop-phases.ps1` throws when an app is unassigned, duplicated or unknown, so a forgotten phase fails loudly instead of being skipped.
- **Re-runs skip installed apps:** `core/scoop-phases.ps1` exposes `Get-SkoopInstalledApps` (checks `apps\<name>\current` under `$SCOOP`, `~/scoop` or ProgramData, so no locale-dependent `scoop list` parsing) and `Invoke-SkoopPhases -SkipInstalled` removes those apps from each generated phase manifest; a phase with no pending apps is not imported at all (but its `-AfterPhase` callback still runs). Both bootstraps pass `-SkipInstalled`; `-ForceInstall` / `-Force` / `$env:SKOOP_FORCE_INSTALL=1` defeats the check for Scoop apps only and is forwarded through `Get-SkoopReLaunchArgs`. An explicit `-ExcludeApps` (e.g. the deliberate UniKey skip) is never overridden by `-Force`. Keep the option, the help text and README's "Updating this machine later" section in sync.
- **Phased install:** `manifests/scoop.json` stays the source of truth for versions; `manifests/phases.json` only maps app names to ordered phases. `core/scoop-phases.ps1` validates the mapping, generates one temporary `{ buckets, apps }` manifest per phase (only the buckets that phase needs) and runs `scoop import` in order. Phase 1 (`core-terminal`: git, pwsh, rio, herdr, herdr-core, vicinae, JetBrainsMono-NF, tailscale) is the fast essentials: Rio is deliberately installed before Herdr, and `install.ps1` finishes Rio/Vicinae/Herdr setup, starts Tailscale and runs `tailscale up --qr` for sign-in, then re-launches under pwsh immediately after it; `-EssentialsOnly` stops there. Later phase failures are reported and skipped so a slow download cannot take the essentials down; phase 1 failures are fatal.
- **Buckets must exist before their apps**; if you introduce a new bucket, add it to `buckets`, list it on the phase(s) that need it, and make sure `install.ps1`/`bootstrap.ps1` still import cleanly (buckets are git repos, hence the git step).
- The `kbots` app builds from a pinned source commit (no deploy tag needed); `bun`, `rustup`, `mingw` and `git` are already in `manifests/scoop.json`. Its install does not start the daemon — run `kbots daemon start` after setup.
- Tailnet tagging: both bootstraps call `apps/tailscale/configure.ps1` after starting Tailscale. It advertises `tag:public-client` on the current device only when connected and the tag is not already advertised; failures are non-fatal. The tailnet ACL must allow the user to own that tag. `-SkipTag` opts out when the script is run directly. `-SignIn` runs `tailscale up --qr` first when the node is not connected, which is how the `core-terminal` phase gets the login URL/QR on screen before Firefox is installed. The `core-terminal` call also passes `-RestoreVicinae`: once a fresh `status --json` probe confirms `BackendState=Running` and `Self.Online`, the script invokes `core/restore-backup.ps1 -Only vicinae` (using `-BackupUser` / `SKOOP_BACKUP_USER`) and writes `%LOCALAPPDATA%\skoop\vicinae-restore-on-connect.done` so re-runs skip the download. `-ForceVicinaeRestore` repeats it; restore failures are non-fatal and never block install or tagging. Piped installs must fetch `core/restore-backup.ps1` alongside `apps/tailscale/configure.ps1`.
- **Scripts target Windows PowerShell 5.1+** with `$ErrorActionPreference = 'Stop'`, and must run without admin unless explicitly elevated. Avoid PowerShell 7-only syntax.
- **Idempotence matters.** `install.ps1`/`bootstrap.ps1` and `shell/profile.ps1` may run repeatedly; check before appending to `$PROFILE` and guard optional commands with `Get-Command ... -ErrorAction SilentlyContinue`.
- **Default mode is Full, not a menu.** A bare `.\install.ps1` (or piped `irm ... | iex`) must run the full setup without asking which mode to use. The gum/numbered selector is opt-in via `-Menu` / `SKOOP_MENU=1`; `-NoMenu` stays as a no-op and `SKOOP_NO_MENU=1` overrides `-Menu`. Forward `-Menu` through `Get-SkoopReLaunchArgs` (except when re-launching with `-SkipMenu`) so a chosen mode survives the pwsh re-launch.
- **Local checkouts live in `~/repos`.** Both bootstraps call `Ensure-SkoopClone` after git is available: it creates `%USERPROFILE%\repos` and clones `KeiosStarqua/skoopub` into `~/repos\skoopub` when that folder is missing (the clone URL is derived from `-RepoRawBase`, so forks work). An existing directory or checkout is never touched, and a failed clone is non-fatal. Piped installs keep using the files fetched to `%LOCALAPPDATA%\skoop` for that run; subsequent runs can use the local checkout.
- **Rio first, then Herdr, and Herdr is opened for you.** Phase 1 installs `rio` before `herdr`/`herdr-core`; after the essentials setup both bootstraps call `Start-HerdrInRio`, which opens `rio -w <~/repos> -e pwsh -NoLogo -NoExit -Command herdr`. It skips non-interactive shells, Herdr panes (`HERDR_ENV=1`) and `-NoAutoHerdr` / `SKOOP_NO_AUTO_HERDR=1`, and clears all six `HERDR_*` markers before `Start-Process` so the child is not mistaken for a nested session. Keep this opt-out switch in `Get-SkoopReLaunchArgs` and the help/docs.
- **Hook both profile editions:** PowerShell 5.1 (`Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`) and 7+ (`Documents\PowerShell\Microsoft.PowerShell_profile.ps1`) use separate files, and `install.ps1` re-launches into pwsh. `Get-ProfileTargets` returns the current `$PROFILE` plus the other edition's path (via `[Environment]::GetFolderPath('MyDocuments')`, so OneDrive redirection is respected), and `Install-ProfileHook` rewrites the dot-source line in each. Stale-hook detection matches the installer's marker comment plus the dot-source line after it (and any dot-source under the repo root), so an old path such as the pre-refactor `<repo>\profile.ps1` is replaced even when the repo folder is renamed. Compare hook text with `\r\n` normalised to `\n`, otherwise 5.1 and 7 rewrite each other's file on every run.
- **Interactive Herdr peer choice:** `.\install.ps1 -HerdrPeer` is a switch (no value) and always opens the gum peer picker; `-Peer <ip|name>` skips it, `-HerdrUser` presets the SSH user. Never commit a machine name or tailnet IP into tracked files — pass them at runtime (arguments or `SKOOP_HERDR_PEER` / `SKOOP_HERDR_USER` env vars for piped runs).
- **gum pickers:** gum draws its UI on **stderr** and writes only the answer to **stdout**. Do not capture it with `... 2>&1 | Out-String` (no terminal → gum draws nothing and returns no choice) and do not simply let PowerShell inherit stderr (PS 5.1 raises a terminating `NativeCommandError` for every UI frame under `$ErrorActionPreference='Stop'`). `Invoke-GumPicker` in `install.ps1` / `apps/herdr/setup-ssh.ps1` starts gum via `System.Diagnostics.ProcessStartInfo` with `RedirectStandardOutput = $true` and `RedirectStandardError = $false`, then reads the answer from `StandardOutput`. `-NoGum` / `$env:SKOOP_NO_GUM=1` still forces the numbered prompt when a terminal cannot render gum at all.
- **Execution policy:** `Set-SkoopExecutionPolicy` in both `install.ps1` and `core/bootstrap.ps1` sets `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` before `Install-ProfileHook`, so the dot-sourced profile loads in new shells (Rio included) instead of erroring with *"running scripts is disabled on this system"*. It skips when CurrentUser is already `RemoteSigned`/`Unrestricted`/`Bypass` and reports failures non-fatally (Group Policy can lock the scope). After `Install-ProfileHook`, `Test-SkoopProfileLoads` in both bootstraps spawns a fresh `powershell.exe` **with** its profile and checks for `Clear-HerdrEnv` from `shell/profile.ps1`, catching a Restricted policy or a stale hook; a failure is printed in red but is non-fatal. Keep both copies in sync with the install section of `README.md`.
- **PowerShell 7 preference:** `install.ps1` re-launches itself with `pwsh -NoProfile -File <script> <same args>` when it is running under Windows PowerShell 5.1 and `pwsh` is already on PATH, because 5.1 mangles native stderr and BOM-less UTF-8. It checks again right after phase 1 installs `pwsh`, so the rest of the run (phases 2-4 and every configure step) already executes under 7; that second launch adds `-NoMenu` (harmless now that the menu is opt-in via `-Menu`) and inherits `SKOOP_PWSH_RELAUNCHED=1` so it cannot loop. `-NoPwsh` / `$env:SKOOP_NO_PWSH=1` opts out; piped `irm ... | iex` runs (no `$PSCommandPath`) and `bootstrap.ps1` keep running in the invoking shell. Keep scripts 5.1-compatible — the re-launch is an optimisation, not a requirement.
- **Keep the three docs in sync** when behavior changes: `README.md` (users), `AGENTS.md` (inventory/conventions), and the comment-based help in `install.ps1`.
- **Verify changes** with `scoop export` (manifest fidelity) and by re-running the affected script in a fresh `powershell` process; there is no automated test suite.
- **Dark mode:** `core/set-dark-mode.ps1` is the single place for the OS theme: it reads `AppsUseLightTheme` / `SystemUsesLightTheme` under HKCU `...\Themes\Personalize`, sets both to `0` only when either is light, and best-effort broadcasts `ImmersiveColorSet`. Both bootstraps call it near the end (non-fatal), and piped installs fetch it alongside `core/scoop-phases.ps1`; keep those three references in sync when editing it.
- **ShareX PrtSc fix is check-first:** `apps/sharex/fix-printscreen.ps1` reads `HKCU:\Control Panel\Keyboard\PrintScreenKeyForSnippingEnabled` (requires a DWORD `0`) and checks whether `ApplicationConfig.json` / `HotkeysConfig.json` already exist before writing anything. When everything is already correct it prints `already applied - no changes needed` and returns - no registry rewrite and no ShareX restart, so repeated bootstrap runs stop re-applying it. `-Force` is the explicit re-apply/restart escape hatch, `-RestartExplorer` still forces an Explorer restart and `-NoRestart` skips the ShareX restart. Both bootstraps call it (install.ps1 step label `Checking ShareX PrtSc fix`, core/bootstrap.ps1 step 9); keep the install.ps1 comment-based help bullet and README step 10 in sync.
- **Mouse diagnostics:** diagnostics come before correction. `.github/workflows/mouse-release.yml` builds the Rust exe on `mouse-v*` tags; `apps/mouse/configure.ps1` downloads that asset and `apps/mouse/mouse.ps1` is the CLI. `fix` installs a `WH_MOUSE_LL` hook and only enables inversion when `diagnose` shows >= 5 mismatches and >= 60% mismatch; `restore` stops it. Do not auto-toggle registry, drivers or cafe-management software from this module, and keep the security note in `apps/mouse/README.md` (public PCs with broken activation/update/Defender) accurate.
- **Editor config:** keep Zed user config in `apps/zed/` and re-run `.\apps\zed\configure.ps1` after edits. Never put credentials, API keys or tokens in these public JSON files.
- **UniKey auto config:** `apps/unikey/configure.ps1` is called by both bootstraps after the apps phase (non-fatally, with `-Force:$ForceUniKey`). UniKey 4.6 RC2 from the `zeldrisho` bucket stores settings at `HKCU:\SOFTWARE\PkLong\UniKey`, **not** `HKCU:\Software\UniKey` — only mirror into the legacy path when it already exists. Verified engine enums: `CodeTable=0` is Unicode, `InputMethod=1` is VNI (`0` = Telex), `Vietnamese=1` enables typing, `ShowDlg=0` suppresses the startup dialog, and `AutoUpdate=0` leaves versioning to Scoop. `apps/unikey/unikey.reg` is the sanitized baseline (no `MacroPath` or other absolute paths); the script stops UniKey before importing it, scrubs stale `MacroPath` values, creates `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\UniKey.lnk` and starts the tray app. `-InputMethod Telex` switches method, `-NoAutostart` / `-NoLaunch` opt out, `-RemoveAutostart` removes the shortcut, `-Export` writes a DWORD-only `.reg` to `%LOCALAPPDATA%\skoop\unikey\backups`, and `-Restore [-Path <file>]` imports the repo baseline or a backup (still enforcing Unicode / Vietnamese / the chosen method). Keep the piped-install fetch list in `install.ps1` and the README/AGENTS references in sync.

## Git workflow

- **Auto commit and push.** After finishing a change, commit and push it to `origin`
  without waiting to be asked. Stage only the files you touched (`git add <paths>`),
  write a concise imperative message (e.g. `Add one-shot install script and README`),
  then `git push`. Don't sweep unrelated work-in-progress into the commit; if the push
  is rejected, `git pull --rebase` and retry once.
- Skip the commit/push only when the user explicitly asks you not to, or when the change
  is unverified and the user wants to review it first.

## Notes

- This repo is not itself a Scoop bucket and publishes no manifests; it adds the `kbots` bucket from `https://github.com/KeiosStarqua/kbots` in `manifests/scoop.json`. `install.ps1` is fetched raw from `https://raw.githubusercontent.com/KeiosStarqua/skoopub/main/install.ps1` (override with `-RepoRawBase`).
- Tailscale installs its service separately; the Scoop package provides the CLI (`tailscale`, `tailscaled`) and needs `tailscaled` running before `tailscale status` works. Both bootstraps now start the Windows `Tailscale` service (and set it to Automatic) when present, otherwise launch the Scoop `tailscaled` shim; sign-in stays interactive. `core-terminal` calls `apps/tailscale/configure.ps1 -SignIn`, which runs `tailscale up --qr` so the login URL/QR is printed in the terminal before Firefox is installed; already-connected nodes skip it. The Windows CLI may be missing from PATH (the official installer does not add it) or unable to talk to the daemon while Tailscale itself works. Both bootstraps probe it with `tailscale status` and print sign-in advice without failing; `apps/herdr/setup-ssh.ps1` resolves `tailscale.exe` from PATH, Program Files and Scoop, and if it still cannot list peers, asks for the machine's Tailscale IP / MagicDNS name (`-Peer` supplies it non-interactively). Peer listing is the only CLI-dependent step; never make the network setup itself depend on the CLI.
- `zeldrisho/scoop-bucket` is third-party: the UniKey manifest installs the official `unikey.org` archive with a pinned SHA-256 hash. Verify the diff when bumping versions.
- `hoilc/scoop-lemon` is third-party and supplies `cava` (Scoop's `extras` bucket has no cava manifest). Its manifest installs the official `karlstav/cava` Windows MSI with a pinned SHA-256 hash; verify the diff when bumping versions. Add it to `manifests/scoop.json` buckets before the app, like any other bucket.
- Public PCs may already have UniKey installed outside Scoop. Both bootstraps detect it (running `UniKeyNT`, uninstall registry, existing Scoop app dir) and import a temporary manifest without `unikey`; `-ForceUniKey` overrides.
- Rust: `rustup` installs the toolchain into `persist\rustup`; the bootstraps only set GNU as default when `rustup show active-toolchain` fails, so an existing MSVC choice survives. Cargo's bin is on the user PATH via the Scoop manifest. A fresh `rustup` writes "no active toolchain" to stderr and exits 1; under `$ErrorActionPreference = 'Stop'` that is a terminating `NativeCommandError` in PowerShell 5.1, so both scripts run the check via `cmd /c ... 2>&1` and inspect `$LASTEXITCODE` instead.
- Firefox: the bootstraps call `firefox --setDefaultBrowser` after installing it (skipped when http is already handled by Firefox). Direct `UserChoice` registry writes are blocked on modern Windows, and Windows 11 may open Settings for confirmation; failures are non-fatal.
- Firefox extensions: `apps/firefox/policies.template.json` is copied to `<scoop>\apps\firefox\current\distribution\policies.json` (Scoop persists that folder) and auto-installs Bitwarden and "I still don't care about cookies" (both AMO) plus mymind (pinned vendor XPI URL) with `normal_installed`. It also sets `DisplayBookmarksToolbar: always`, a `skoopub` managed-bookmarks folder (Hacker News, mymind, Scoop, OpenCode, YouTube to Transcript), and `Homepage` (ChatGPT as URL with `StartPage: homepage`). It disables the built-in password-saving prompt via `OfferToSaveLogins: false` plus `OfferToSaveLoginsDefault: false` (Bitwarden handles logins). Firefox reads policies at startup, so restart it after the first setup; switch to `force_installed` only if an extension should be locked.
- Firefox version: only Firefox is pinned. Its `manifests/scoop.json` entry uses `Source: "<auto-generated>"` with `Version: "161.0"` plus `Info: "Held package"`, so `scoop import` runs `scoop install firefox@161.0` (resolved from the extras bucket's manifest history) and then `scoop hold`, keeping the deployed policy on a known version. This is the exception to the usual `{Info, Source, Name}` bucket-app shape; every other app stays on its bucket's latest. To upgrade, bump `Version` and run `scoop unhold firefox` before importing (a held app cannot be updated).
- GitHub auth: `gh auth login` alone does not configure git. `apps/github/setup-auth.ps1` runs `gh auth setup-git`, which writes `credential.https://github.com.helper` (`gh auth git-credential`) so `git push` uses the gh token via HTTPS. Both bootstraps call it after the ShareX fix; `-SkipGhLogin` makes that step non-interactive, and failures are non-fatal.
- Herdr remote: `apps/herdr/setup-ssh.ps1` uses Tailscale SSH, so no key pair, password or `~/.ssh/config` edit is needed. The target machine must have Tailscale SSH enabled (`tailscale set --ssh=true`) and the tailnet SSH policy must permit the login; a rejection names the user that was tried, which `-User` can override. The script probes users without prompting and saves the machine with `herdr machine add <user>@<machine> --label <machine>`: Herdr prepares the remote server and keeps the profile, so it shows up in the sidebar of every open client. Nothing is started with `herdr --remote`, and an already-saved target is left untouched (`herdr machine list` is checked first because `machine add` would otherwise create a duplicate profile), so running `install.ps1` → "Connect Herdr only" from inside a pane is safe. Never put a machine name or tailnet IP in tracked files; peer addresses come only from `tailscale status` or the runtime prompt.
- Zed's in-app auto-update is disabled in `apps/zed/settings.json` (`auto_update: false`); otherwise it installs outside Scoop and the pinned version in `manifests/scoop.json` stops matching reality. `innounp` is pulled in automatically as the installer dependency.
- Zed config lives in `%APPDATA%\Zed` (`settings.json`, `keymap.json`, `tasks.json`, `themes/`, `snippets/`); extensions install into `%LOCALAPPDATA%\Zed\extensions`. `apps/zed/configure.ps1` is called by both bootstraps after gh auth and copies `apps/zed/*.json` there with timestamped backups before overwriting (`-NoBackup` skips that). Piped installs fetch `apps/zed/*.json` to `%LOCALAPPDATA%\skoop\zed`.
- Zed extensions: `auto_install_extensions` declares PowerShell, HTML, Dockerfile, Docker Compose, TOML, Nix and SQL; Zed installs them at startup. The PowerShell extension needs `pwsh` (now in `manifests/scoop.json`); Rust needs no extension because Zed ships `rust-analyzer` natively, so `lsp.rust-analyzer` is configured instead of a nonexistent `rust` extension ID.
- Rio config: `apps/rio/config.toml` sets `[fonts] size = 16`; Rio has no separate zoom setting, so this is the zoom level. `apps/rio/configure.ps1` copies it to `%LOCALAPPDATA%\rio\config.toml` with a timestamped backup of a changed original unless `-NoBackup`, and Rio hot-reloads the file without a restart. Both bootstraps call it right after the `core-terminal` phase, so the terminal is usable before the slower phases; piped installs fetch `apps/rio/config.toml` and `apps/rio/configure.ps1` to `%LOCALAPPDATA%\skoop`.
- Git identity: `apps/git/setup-identity.ps1` writes `user.name = Keios` and `user.email = git@taquangkhoi.com` to the global git config so all commits are attributed correctly. `-Local` targets the current repository and `-Name` / `-Email` override the defaults; the script is idempotent and called by both bootstraps after gh auth.
- Komorebi hotkeys / padding / workspace rules: `apps/komorebi/whkdrc` and `apps/komorebi/komorebi.json` are deployed to `%USERPROFILE%\.config` with timestamped backups of changed originals unless `-NoBackup`. The JSON sets tight gaps (`default_workspace_padding: 4`, `default_container_padding: 2`) instead of Komorebi's 10px defaults and a slim `border_width: 3` instead of the 8px default, enables hover-to-focus with `"focus_follows_mouse": "Windows"` (the native implementation; `"Komorebi"`'s own implementation did not change focus in testing) and disables the competing cursor jump with `"mouse_follows_focus": false` (Komorebi 0.1.41 still supports this config-only option, though upstream marks it end-of-life in favour of the separate `masir` tool, which is not in Scoop), uses `Columns` on the Terminal workspace, and names nine workspaces with `initial_workspace_rules` (assign on first appearance; manual moves still allowed): Firefox + Rio on workspace 0 (`Win+1`), Zed + VS Code + Pear Desktop ("YouTube Music.exe") + YASB Themes ("yasb_themes.exe") on workspace 1 (`Win+2`), Chrome on 2, Discord/Telegram on 3, Explorer on 4, Spotify/VLC on 5, 6–8 spare. Rules are loaded into Komorebi's global state; already-open windows are not moved, so relaunch an app or use `komorebic enforce-workspace-rules` if you want existing windows rearranged. `komorebic replace-configuration` applies the config to an already-running daemon, and `komorebic start -c` uses it on a fresh start. Komorebi cannot pin an app to a column declaratively, so `apps/komorebi/pin-terminal-layout.ps1` polls the state and reorders the Terminal columns to keep Rio left / Firefox right; it is started hidden and added to Startup by `apps/komorebi/configure.ps1` unless `-NoPin` (`-RestartPin` relaunches it). `apps/komorebi/configure.ps1` starts Komorebi when needed and starts/reloads `whkd`; `-NoStart` only deploys and `-Restart` forces a reload. The scheme uses `Win` as the primary modifier (Hyprland-style): `Win+Arrow` focus, `Win+Shift+Arrow` move, `Win+Ctrl+Arrow` resize, `Win+1..9` workspaces. H/J/K/L are avoided because Windows 11 reserves `Win+H/J/K/L`; Firefox is `Win+Shift+W` (not `Win+Shift+B`, which resets the graphics driver). `Win+Arrow` may still be captured by Snap layouts. whkd uses `.shell powershell` so it does not depend on `pwsh` being on PATH. After Komorebi is installed and started, `apps/komorebi/configure.ps1` runs `apps/komorebi/set-taskbar-autohide.ps1` last (so the Explorer restart cannot interrupt Komorebi/whkd startup): it checks `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\StuckRects3\Settings` byte 8 and writes `0x03` only when it is not already auto-hide, then restarts Explorer once to apply it; YASB is the visible bar so the stock taskbar is hidden. Both scripts are idempotent and the change is non-fatal, `-NoTaskbarAutohide` opts out of the configure step, and `set-taskbar-autohide.ps1 -Disable` restores `0x02` (always-on-top), with `-NoRestart` deferring the Explorer restart to next sign-in. Keep the piped-install fetch list in `install.ps1` and the docs (README help bullet, command table, AGENTS index/convention) in sync when editing either script.
- YASB config: `apps/yasb/` is vendored from SleepyCatHey/Ultimate-Win11-Setup (YASB config for Komorebi). `apps/yasb/configure.ps1` copies `config.yaml` and `styles.css` to `%USERPROFILE%\.config\yasb` with timestamped backups unless `-NoBackup`, creates `.env` from `.env.example` when missing, and starts YASB (`-Restart` forces a restart). Weather uses `YASB_WEATHER_API_KEY` / `YASB_WEATHER_LOCATION` from `.env`, wallpapers use `YASB_WALLPAPER_DIR`; never commit real credentials. In-app updates are off (`update_check: false`) so Scoop owns the version, and the cava widget uses the `cava` app from the `lemon` bucket in `manifests/scoop.json`.
- Nushell shortcut: `shell/profile.ps1` defines `n` → `nu` only when Nushell is installed and no `n` alias already exists. `apps/nushell/setup.ps1` writes `%LOCALAPPDATA%\skoop\nu-autostart.cmd` containing `doskey n=nu $*` and appends it to HKCU `Command Processor\AutoRun` only if absent, preserving existing entries; `-Remove` undoes both. This is an alias, not a shell replacement — PowerShell/cmd still start normally.
- Starship prompt: `apps/starship/starship.toml` is the repo copy; `apps/starship/configure.ps1` deploys it to `%USERPROFILE%\.config\starship.toml` (Starship's default path, so no `STARSHIP_CONFIG`). PowerShell loads it from `shell/profile.ps1` (`starship init powershell`, skipped when `starship` is missing or `(Get-Command prompt).Source` is already `starship`). cmd.exe has no prompt hook of its own, so it needs Clink (in `manifests/scoop.json`): the script writes `%LOCALAPPDATA%\clink\starship.lua` with the documented `load(io.popen('starship init cmd'):read('*a'))()` line and runs `clink autorun install`. Clink appends its command to cmd's AutoRun value, so the Nushell doskey entry survives; the script re-checks AutoRun and warns if it vanished. Both files are written as UTF-8 **without BOM** — PowerShell 5.1's `Get-Content -Raw` default decodes BOM-less files as ANSI (mojibake glyphs) and `Set-Content -Encoding UTF8` adds a BOM, which Starship's TOML parser and Clink's Lua loader reject, so the script uses `[System.IO.File]::ReadAllText/WriteAllText` with explicit UTF-8. `-NoCmd` / `-NoAutorun` opt out; Clink absent just prints a hint.
- Vicinae shortcut: `apps/vicinae/keybinds.json` sets `global_shortcuts.toggle` to `control+space`. `apps/vicinae/configure.ps1` copies it into `%LOCALAPPDATA%\vicinae\config` and adds `"./keybinds.json"` to `settings.json`'s `imports`, so GUI edits never overwrite it. Vicinae reads global shortcuts at server start, so re-run with `-Restart` after changing the binding.
- Vicinae: the global shortcut only works while `vicinae-server.exe` is running. Scoop ships the server and a Start Menu shortcut but no login autostart, so `apps/vicinae/enable-autostart.ps1` creates a per-user Startup `.lnk` targeting `apps\vicinae\current\bin\vicinae-server.exe` and starts it immediately. It is idempotent (repairs shortcuts pointing at versioned folders), non-fatal in both bootstraps, and `-Remove` / `-NoLaunch` give an opt-out. Because the installer may run inside a Herdr pane, the script clears `HERDR_ENV`/`HERDR_PANE_ID`/etc. before starting the server; otherwise every terminal launched from Vicinae inherits them and `herdr` refuses to start with the "nested herdr"/inception message. Use `-Restart` on an existing contaminated server.
- Shutdown cleanup: `core/cleanup-before-shutdown.ps1` runs from the per-user `SkoopCleanupOnShutdown` task registered by `core/install-shutdown-hook.ps1`. It uploads Firefox profiles / Vicinae config+data+state / Atuin config+data to `acer-ubuntu` and removes auth only after verification. Besides GitHub/git/Windows credentials, SSH keys and Firefox logins, it calls `tailscale logout` (resolving `tailscale.exe` from PATH, Program Files or Scoop, since the official installer omits PATH; failures are non-fatal) and deletes Pear Desktop's userData (`%APPDATA%\YouTube Music`, plus `%LOCALAPPDATA%` and `Pear Desktop` variants) so no Google login or cache is left behind. Pear/Tailscale cleanup is skipped by `-BackupOnly` and previewed by `-DryRun`. The `tag:public-client` advertisement set by `apps/tailscale/configure.ps1` is not explicitly removed — logout revokes the signed-in node identity.
- Backup/restore layout: the cleanup keeps **separate** snapshots per app — Firefox at `~/skoop-backups/firefox/<timestamp>/firefox` (unchanged layout), Vicinae at `~/skoop-backups/vicinae/<timestamp>/vicinae` (`config`, `data`, `state`; `cache` is skipped) and Atuin at `~/skoop-backups/atuin/<timestamp>/atuin` (`config.toml`, optional `server.toml` and the `data` folder with history/records/meta databases, `key` and SQLite sidecars). `core/restore-backup.ps1` is a standalone, opt-in companion (used automatically only for Vicinae after Tailscale connect): it picks the newest timestamp for each app independently and merges them back, rather than expecting one coherent snapshot for all three. It never touches the remote host. `-Only`, `-Stamp`, `-List`, `-DryRun`, `-NoBackup` and `-NoRestart` give control; Firefox must be closed (locked profile files) and a running `vicinae-server` is stopped/restarted around the copy. Atuin is per-shell (no service to stop), but the restore deletes stale `*.db-wal` / `*.db-shm` first so a restored DB is not replayed against local journal data, and warns to close other Atuin shells; the archive contains the encryption key and command history, so protect it. After restoring on a fresh machine, re-run `.\apps\vicinae\configure.ps1 -Restart` if the managed keybinds were changed outside the repo. `-NoVicinae` / `-NoAtuin` skip those snapshots on the backup script.
