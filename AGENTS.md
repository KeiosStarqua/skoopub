# AGENTS.md

Index of this repository for agents and humans. **skoop** is a declarative Windows
dev setup: [Scoop](https://scoop.sh) packages plus a repo-managed PowerShell profile,
restored from one manifest. There is no build system, no tests, and no package
manager of its own — the files are the product.

## Conventions

### Repository organization rules

- **Architecture:** feature-based, application-centric directories. `apps/<application>/` holds that application's scripts, configs, templates and fixes; `core/` holds shared orchestration; `shell/` the shared PowerShell profile; `manifests/` package manifests; future `tests/` and `docs/` folders are optional.
- **Root directory:** keep it minimal -- public entry points (`install.ps1`, `bootstrap.ps1`), documentation and metadata only. No application-specific scripts or configs in the root.
- **Application isolation:** every managed app owns a directory under `apps/`. All app-specific files live there; do not create global `configs/`, `fixes/` or `scripts/` folders.
- **Naming:** lowercase kebab-case for files/directories. Do not repeat the application name in a filename when the parent directory already identifies it. Use standard names (`configure.ps1`, `setup.ps1`, `install.ps1`, `uninstall.ps1`, `update.ps1`, `verify.ps1`, `enable-autostart.ps1`, `fix-<issue>.ps1`, `*.template.json`), preserving names required by third-party apps.
- **Script design:** scripts must be idempotent and independent of the current working directory; resolve repo-relative paths from `$PSScriptRoot` plus `Join-Path`. Keep app logic inside its app directory; extract genuinely shared logic into `core/`. Root `install.ps1` is the public entry point and delegates app-specific work.
- **When moving or renaming:** use `git mv`; update all script references and relative paths; update README.md/AGENTS.md and both bootstraps; preserve command-line arguments and public behaviour; verify no references to old paths remain; test the affected installation/configuration flows before finishing.
- Do not add unnecessary directories, empty placeholder scripts or abstractions without a concrete requirement.
- **Add or remove a package** by editing `manifests/scoop.json`; keep the `{ "Info": "", "Source": ..., "Name": ... }` shape and keep apps grouped by source. Real-world workflow: `scoop install <app>` then `scoop export | Out-File -Encoding utf8 manifests/scoop.json` (verify the diff before committing). Every app must also appear in exactly one phase in `manifests/phases.json`; `core/scoop-phases.ps1` throws when an app is unassigned, duplicated or unknown, so a forgotten phase fails loudly instead of being skipped.
- **Re-runs skip installed apps:** `core/scoop-phases.ps1` exposes `Get-SkoopInstalledApps` (checks `apps\<name>\current` under `$SCOOP`, `~/scoop` or ProgramData, so no locale-dependent `scoop list` parsing) and `Invoke-SkoopPhases -SkipInstalled` removes those apps from each generated phase manifest; a phase with no pending apps is not imported at all (but its `-AfterPhase` callback still runs). Both bootstraps pass `-SkipInstalled`; `-ForceInstall` / `-Force` / `$env:SKOOP_FORCE_INSTALL=1` defeats the check for Scoop apps only and is forwarded through `Get-SkoopReLaunchArgs`. An explicit `-ExcludeApps` (e.g. the deliberate UniKey skip) is never overridden by `-Force`. Keep the option, the help text and README's "Updating this machine later" section in sync.
- **Phased install:** `manifests/scoop.json` stays the source of truth for versions; `manifests/phases.json` only maps app names to ordered phases. `core/scoop-phases.ps1` validates the mapping, adds a phase's buckets with one import, then generates one temporary `{ buckets, apps }` manifest per app, runs `scoop import` in order and prints a per-package time table (`package times:`) plus the phase total. Per-app manifests declare no buckets, so `New-SkoopPhaseManifest` rewrites a bucket `Source` to `bucket/app` — `scoop import` only maps `Source` to `bucket/app` when that bucket is in the same file, otherwise it tries to install the bucket name itself. Because `scoop import` ignores its child `scoop install` exit code and still returns 0 on failure, `Test-SkoopAppInstalled` checks the app's `current` dir after each import and marks the package as failed when the install did not happen. On PowerShell 7 the app imports inside a phase run in parallel (`-ThrottleLimit`, default 4; 1 = sequential; 5.1 always sequential); phases and callbacks stay strictly ordered. Phase 1 (`core-terminal`: git, pwsh, rio, alacritty, wezterm, herdr, herdr-core, vicinae, JetBrainsMono-NF, JetBrainsMono-NF-Propo) installs the terminal and the Herdr TUI first: Rio is deliberately installed before Herdr, `install.ps1` refreshes the process `PATH` / resolves Scoop executables, applies the Rio config, opens Rio with Herdr already running (skipped when a `rio` process is already open, so repeated install runs do not stack windows), and re-launches under pwsh immediately after it. Phase 2 (`tailscale`) installs and signs in to Tailscale, then restores every acer-ubuntu snapshot before GitHub auth and the repo clones; `-EssentialsOnly` stops after it. Later phase failures are reported and skipped so a slow download cannot take the essentials down; phase 1 failures are fatal.
- **Buckets must exist before their apps**; if you introduce a new bucket, add it to `buckets`, list it on the phase(s) that need it, and make sure `install.ps1`/`bootstrap.ps1` still import cleanly (buckets are git repos, hence the git step).
- The `kbots` app builds from a pinned source commit (no deploy tag needed); `bun`, `rustup`, `mingw` and `git` are already in `manifests/scoop.json`. Its install does not start the daemon — run `kbots daemon start` after setup.
- Ollama is installed as `extras/ollama-full` in the `apps` phase (extra bucket already listed there). Do **not** swap it for `main/ollama`: that manifest is CLI-only and its note says the daemon moved to `ollama-full`, so `ollama run` would have no server. Models are never pulled by the bootstrap (multi-GB); users pull them themselves. No `apps/ollama/` directory is needed — Scoop supplies the `ollama` shim. Keep the README Ollama row in sync.
- Tailnet tagging: `install.ps1` installs Tailscale in its own phase (phase 2, right after the terminal/Herdr phase), caches `-BackupUser` / `SKOOP_BACKUP_USER` in `%LOCALAPPDATA%\skoop\backup-user`, and its phase callback installs OpenCode and Firefox with Scoop from their `manifests/scoop.json` entries (one-app `scoop import`, so the CLI/browser are usable as soon as their backups are restored), starts the daemon and calls `apps/tailscale/configure.ps1 -SignIn` with the full restore set, before the `gh auth login` prompt and the repo clones. `core/bootstrap.ps1` keeps its earlier sign-in and installs the Scoop CLI from the `extras` bucket when neither a CLI nor an official Program Files client exists. A missing OpenCode or Firefox snapshot throws and aborts the install before auth/clones (`-SkipFirefoxRestore` only opts out of Firefox). `Start-TailscaleDaemon` also starts the tray from its `Scoop Apps` Start Menu shortcut (`Tailscale.lnk`, falling back to `apps\tailscale\current\tailscale-ipn.exe`) or uses the Windows service when present, and imports the package's `add-startup.reg` into HKCU Run so the tray/daemon comes back after sign-in; it resolves `tailscaled.exe` from that folder when there is no service (no shim exists). Windows keys the notification-area entry on the shortcut/executable identity, so the shortcut is used instead of a versioned path. After a successful connect, `configure.ps1` calls `Start-TailscaleTray`, which restarts a tray running from an older versioned folder and starts the current one from the same shortcut, keeping the icon and its "Authentication Needed" notification visible. After a successful sign-in, `configure.ps1` waits up to 30 s for `status --json` to report `Running`/`Self.Online` before tagging or restoring, avoiding the "Tailscale is starting / NoState" false negative. They then call `apps/tailscale/configure.ps1` again at the end as a safety net. The tag is advertised **before** the snapshot restores, because the tailnet ACL may only let tagged devices reach acer-ubuntu; the per-app restore children run with `-SkipTag` so it is advertised exactly once. It advertises the tag on the current device only when connected and the tag is not already advertised; after a tag change it waits for `status --json` to report Online again before the restores SSH out. When any restore switch is set, a tag that cannot be applied is a **hard error** (the ACL would refuse the restores anyway); outside the restore flow it only warns. The tailnet ACL must allow the user to own that tag. `-SkipTag` opts out when the script is run directly. `-SignIn` runs `tailscale up --qr` first when the node is not connected. The QR opens in a new Rio window (`Start-TailscaleQrWindow`), because a legacy conhost with code page 437 renders its Unicode blocks as mojibake; an already-running `tailscale up --qr` is reused instead of stacking windows, the window closes itself once the command returns, and the parent polls `status --json` for up to `-SignInTimeout` seconds (default 600, 0 = wait forever). Without Rio/pwsh the QR streams in the current console with UTF-8 forced. The tailscale phase callback passes `-RestoreVicinae`, `-RestorePearDesktop`, `-RestoreFirefox`, `-RestoreAtuin` and `-RestoreOpenCode`: once a fresh `status --json` probe confirms `BackendState=Running` and `Self.Online`, it restores OpenCode first, then runs Vicinae/Pear/Firefox/Atuin as parallel child processes (each invoking `core/restore-backup.ps1 -Only <app>` with `-BackupUser` / `SKOOP_BACKUP_USER`) and writes `%LOCALAPPDATA%\skoop\vicinae-restore-on-connect.done` / `pear-restore-on-connect.done` / `firefox-restore.done` / `atuin-restore.done` / `opencode-restore.done` so re-runs skip the download. The callback also restores the SSH key (`-Only ssh`, marker `ssh-restore.done`, `-SkipSshRestore` opts out) and the repo list (`-Only repos`), then configures Vicinae on top of its restored config. Firefox is installed with Scoop just before this restore; Atuin needs no CLI and only has its files laid down. Firefox is closed/relaunched around the copy and Atuin warns to close other shells. `-Force*Restore` repeats one app; restore failures other than the OpenCode/Firefox mandatory ones are non-fatal. `core/bootstrap.ps1` keeps its own step 6 retries. Both bootstraps expose `-ForceFirefoxRestore` / `-ForceAtuinRestore` (env `SKOOP_FORCE_FIREFOX_RESTORE=1` / `SKOOP_FORCE_ATUIN_RESTORE=1`) to repeat one and `-SkipFirefoxRestore` / `-SkipAtuinRestore` (env `SKOOP_NO_FIREFOX_RESTORE=1` / `SKOOP_NO_ATUIN_RESTORE=1`) to opt out; the skip switches are forwarded by `Get-SkoopReLaunchArgs`. All other failures are non-fatal. In `install.ps1` this restore call runs in the `tailscale` phase callback, before `apps/vicinae/configure.ps1` and `apps/vicinae/enable-autostart.ps1`, so the Vicinae database/config/state from the snapshot is restored before the app is configured or launched and the repo-managed keybinds are written on top. Piped installs must fetch `core/restore-backup.ps1` alongside `apps/tailscale/configure.ps1`.
- **Scripts target Windows PowerShell 5.1+** with `$ErrorActionPreference = 'Stop'`, and must run without admin unless explicitly elevated. Avoid PowerShell 7-only syntax.
- **Idempotence matters.** `install.ps1`/`bootstrap.ps1` and `shell/profile.ps1` may run repeatedly; check before appending to `$PROFILE` and guard optional commands with `Get-Command ... -ErrorAction SilentlyContinue`.
- **Default mode is Full, not a menu.** A bare `.\install.ps1` (or piped `irm ... | iex`) must run the full setup without asking which mode to use. The gum/numbered selector is opt-in via `-Menu` / `SKOOP_MENU=1`; `-NoMenu` stays as a no-op and `SKOOP_NO_MENU=1` overrides `-Menu`. Forward `-Menu` through `Get-SkoopReLaunchArgs` (except when re-launching with `-SkipMenu`) so a chosen mode survives the pwsh re-launch.
- **Local checkouts live in `~/repos`.** Both bootstraps call `Ensure-SkoopClone` only after Tailscale sign-in and GitHub auth have been attempted, so private checkouts have a credential helper: it creates `%USERPROFILE%\repos` and clones `KeiosStarqua/skoopub` into `~/repos\skoopub` when that folder is missing (the clone URL is derived from `-RepoRawBase`, so forks work). An existing directory or checkout is never touched, and a failed clone is non-fatal. Piped installs keep using the files fetched to `%LOCALAPPDATA%\skoop` for that run; subsequent runs can use the local checkout. `manifests/repos.json` extends this to the other registered checkouts: `install.ps1` calls `Ensure-RegisteredRepos` right after `Ensure-SkoopClone`, cloning entries with a URL (`git clone -b <branch> <url> ~/repos/<name>`) and skipping entries without an origin, existing `.git` checkouts, and non-git directories that already occupy the target. The clones run **in the background** (`-Background`, `Start-Process` with the git output in `%LOCALAPPDATA%\skoop\repo-clone-<name>.log[.err]`) so the phases behind them start immediately; `Complete-RegisteredRepoClones` waits and reports each one near the end of the run. Failures are non-fatal; `-SkipRepoClones` / `SKOOP_NO_REPO_CLONES=1` opts out and is forwarded by `Get-SkoopReLaunchArgs`. Run `.\core\register-repos.ps1` after cloning a new repo to auto-scan `~/repos` and refresh the manifest (`-DryRun` previews, `-ScanRoot` points elsewhere); it merges updates instead of replacing entries and writes a `.bak` of a changed manifest. Manually adding `{ name, url, branch }` is still fine; remember the piped fetch list.
- **Rio first, then Herdr, and Herdr is opened for you.** Phase 1 installs three terminals - `rio`, `alacritty` and `wezterm` (from `extras`, in `manifests/scoop.json` and `manifests/phases.json`) - with `rio` before `herdr`/`herdr-core`; after the phase 1 callback both bootstraps call `Start-HerdrInRio`, which opens `rio -w <~/repos> -e pwsh -NoLogo -NoExit -Command herdr`. It skips non-interactive shells, Herdr panes (`HERDR_ENV=1`), an already-running `rio` process (so repeated install runs do not stack windows) and `-NoAutoHerdr` / `SKOOP_NO_AUTO_HERDR=1`, and clears all six `HERDR_*` markers before `Start-Process` so the child is not mistaken for a nested session. Keep this opt-out switch in `Get-SkoopReLaunchArgs` and the help/docs.
- **Hook both profile editions:** PowerShell 5.1 (`Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1`) and 7+ (`Documents\PowerShell\Microsoft.PowerShell_profile.ps1`) use separate files, and `install.ps1` re-launches into pwsh. `Get-ProfileTargets` returns the current `$PROFILE` plus the other edition's path (via `[Environment]::GetFolderPath('MyDocuments')`, so OneDrive redirection is respected), and `Install-ProfileHook` rewrites the dot-source line in each. Stale-hook detection matches the installer's marker comment plus the dot-source line after it (and any dot-source under the repo root), so an old path such as the pre-refactor `<repo>\profile.ps1` is replaced even when the repo folder is renamed. Compare hook text with `\r\n` normalised to `\n`, otherwise 5.1 and 7 rewrite each other's file on every run.
- **Interactive Herdr peer choice:** `.\install.ps1 -HerdrPeer` is a switch (no value) and always opens the gum peer picker; `-Peer <ip|name>` skips it, `-HerdrUser` presets the SSH user. Never commit a machine name or tailnet IP into tracked files — pass them at runtime (arguments or `SKOOP_HERDR_PEER` / `SKOOP_HERDR_USER` env vars for piped runs).
- **gum pickers:** gum draws its UI on **stderr** and writes only the answer to **stdout**. Do not capture it with `... 2>&1 | Out-String` (no terminal → gum draws nothing and returns no choice) and do not simply let PowerShell inherit stderr (PS 5.1 raises a terminating `NativeCommandError` for every UI frame under `$ErrorActionPreference='Stop'`). `Invoke-GumPicker` in `install.ps1` / `apps/herdr/setup-ssh.ps1` starts gum via `System.Diagnostics.ProcessStartInfo` with `RedirectStandardOutput = $true` and `RedirectStandardError = $false`, then reads the answer from `StandardOutput`. `-NoGum` / `$env:SKOOP_NO_GUM=1` still forces the numbered prompt when a terminal cannot render gum at all.
- **Execution policy:** `Set-SkoopExecutionPolicy` in both `install.ps1` and `core/bootstrap.ps1` sets `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` before `Install-ProfileHook`, so the dot-sourced profile loads in new shells (Rio included) instead of erroring with *"running scripts is disabled on this system"*. It skips when CurrentUser is already `RemoteSigned`/`Unrestricted`/`Bypass` and reports failures non-fatally (Group Policy can lock the scope). After `Install-ProfileHook`, `Test-SkoopProfileLoads` in both bootstraps spawns a fresh `powershell.exe` **with** its profile and checks for `Clear-HerdrEnv` from `shell/profile.ps1`, catching a Restricted policy or a stale hook; a failure is printed in red but is non-fatal. Keep both copies in sync with the install section of `README.md`.
- **PowerShell 7 preference:** `install.ps1` continues in a **new Herdr tab** when possible and otherwise opens a **new PowerShell 7 window**, then exits the caller when it is running under Windows PowerShell 5.1 and `pwsh` is available, because 5.1 mangles native stderr and BOM-less UTF-8. `Start-SkoopPwshInHerdrTab` resolves `herdr`, waits up to 30 s for the running server, calls `herdr tab create --label 'skoop setup' --cwd <repo> --env SKOOP_PWSH_RELAUNCHED=1 --focus`, reads `.result.root_pane.pane_id` from its JSON, and submits `& "<pwsh>" -NoExit -NoLogo -NoProfile -ExecutionPolicy Bypass -File <script> <same args>` with `herdr pane run`; a failed creation closes the empty tab and falls back to `Start-Process pwsh -ArgumentList "-NoLogo -NoProfile -NoExit -ExecutionPolicy Bypass -File <script> <same args>"` (values with spaces quoted). A new tab/window rather than re-launching in place: the caller may be a 5.1 console or a Herdr pane that must not be taken over, and `-NoExit` keeps the final summary readable. `-NoHerdrTab` / `SKOOP_NO_HERDR_TAB=1` forces the standalone window and `-NoAutoHerdr` implies it; add the switch to `Get-SkoopReLaunchArgs` and keep the help/README docs in sync. It checks again right after phase 1 installs `pwsh`, so the rest of the run (the tailscale phase and every configure step) already executes under 7; the child inherits `SKOOP_PWSH_RELAUNCHED=1` so it cannot loop, and the parent removes it again in `finally` so later `.\install.ps1` runs in that console are not silently stuck on 5.1. ## Git workflow

- **Auto commit and push.** After finishing a change, commit and push it to `origin`
  without waiting to be asked. Stage only the files you touched (`git add <paths>`),
  write a concise imperative message (e.g. `Add one-shot install script and README`),
  then `git push`. Don't sweep unrelated work-in-progress into the commit; if the push
  is rejected, `git pull --rebase` and retry once.
- Skip the commit/push only when the user explicitly asks you not to, or when the change
  is unverified and the user wants to review it first.

- Vicinae shortcut: `apps/vicinae/keybinds.json` sets `global_shortcuts.toggle` to `control+space`. `apps/vicinae/configure.ps1` copies it into `%LOCALAPPDATA%\vicinae\config` and adds `"./keybinds.json"` to `settings.json`'s `imports`, so GUI edits never overwrite it. Vicinae reads global shortcuts at server start, so re-run with `-Restart` after changing the binding.
- Vicinae: the global shortcut only works while `vicinae-server.exe` is running. Scoop ships the server and a Start Menu shortcut but no login autostart, so `apps/vicinae/enable-autostart.ps1` creates a per-user Startup `.lnk` targeting `apps\vicinae\current\bin\vicinae-server.exe` and starts it immediately. It is idempotent (repairs shortcuts pointing at versioned folders), non-fatal in both bootstraps, and `-Remove` / `-NoLaunch` give an opt-out. Because the installer may run inside a Herdr pane, the script clears `HERDR_ENV`/`HERDR_PANE_ID`/etc. before starting the server; otherwise every terminal launched from Vicinae inherits them and `herdr` refuses to start with the "nested herdr"/inception message. Use `-Restart` on an existing contaminated server.
- SSH key backup/restore: `core/cleanup-before-shutdown.ps1` stages `~/.ssh` key files (`id_*`, `*.pub`, `config`; not `known_hosts`) into `~/skoop-backups/ssh/<timestamp>/ssh` and uploads/verifies it **before** `Remove-SshKeys` wipes them (`-NoSsh` skips both). `core/restore-backup.ps1` accepts `ssh` in `-Only` (default includes it), downloads that snapshot and merges the files back into `~/.ssh` with timestamped `.bak` unless `-NoBackup`; `install.ps1` calls `-Only ssh` once in the `tailscale` phase callback with marker `%LOCALAPPDATA%\skoop\ssh-restore.done` and `-SkipSshRestore` / `SKOOP_NO_SSH_RESTORE=1` to opt out (forwarded through `Get-SkoopReLaunchArgs`). Failures are non-fatal. The private key must stay secret: never leave it on a public/shared PC.
- OpenCode ponytail plugin: `install.ps1` adds `@dietrichgebert/ponytail` with `opencode plugin add` near the end (step 20b), but only when `opencode` is on PATH and `~/.config/opencode/opencode.json` does not already list it, so re-runs do not duplicate it or prompt; failures are non-fatal. `core/bootstrap.ps1` does not do this step.
- Shutdown cleanup: `core/cleanup-before-shutdown.ps1` runs from the per-user `SkoopCleanupOnShutdown` task registered by `core/install-shutdown-hook.ps1`. It uploads Firefox profiles / Vicinae config+data+state+Credential Manager master key / Atuin config+data / Pear Desktop userData / OpenCode config+state+exported credentials to `acer-ubuntu` and removes auth only after verification. The SSH key under `~/.ssh` is snapshotted first to `~/skoop-backups/ssh/<timestamp>/ssh` (`-NoSsh` skips both the snapshot and the wipe); `known_hosts` is always removed. Besides GitHub/git/Windows credentials, SSH keys and Firefox logins, it calls `tailscale logout` (resolving `tailscale.exe` from PATH, Program Files or Scoop, since the official installer omits PATH; failures are non-fatal) and deletes Pear Desktop's userData (`%APPDATA%\YouTube Music`, plus `%LOCALAPPDATA%` and `Pear Desktop` variants) so no Google login or cache is left behind. Because Chromium locks the cookie database while the app runs, `Copy-PearDesktopData` stops `YouTube Music` / `Pear Desktop` before copying and refuses to continue when a cookie database that exists locally is missing from the staged snapshot. `Copy-OpenCodeData` copies `~/.config/opencode` and `~/.local/state/opencode` (skipping `service.json`, `locks`, `pty`), runs `opencode auth export` (retrying with `--standalone`) and aborts the wipe when credentials exist but the export fails; `Remove-OpenCodeAuth` logs out every connection using the `auth list --format json` IDs with the plain table as a fallback. Pear/Tailscale cleanup is skipped by `-BackupOnly` and previewed by `-DryRun`; `-NoPear` / `-NoOpenCode` leave those apps completely alone (no snapshot, no sign-out). The `tag:public-client` advertisement set by `apps/tailscale/configure.ps1` is not explicitly removed - logout revokes the signed-in node identity. `shell/profile.ps1` exposes the short `skoop-cleanup` command (same script; `-BackupOnly` uploads without wiping) and reads the SSH user from `$env:SKOOP_BACKUP_USER`, then `%LOCALAPPDATA%\skoop\backup-user` (written by `install.ps1` from `-BackupUser`), so no long path is needed.
- Backup/restore layout: the cleanup keeps **separate** snapshots per app — Firefox at `~/skoop-backups/firefox/<timestamp>/firefox` (unchanged layout), Vicinae at `~/skoop-backups/vicinae/<timestamp>/vicinae` (`config`, `data`, `state` plus `keychain/vicinae-master-key`; `cache` is skipped), Atuin at `~/skoop-backups/atuin/<timestamp>/atuin` (`config.toml`, optional `server.toml` and the `data` folder with history/records/meta databases, `key` and SQLite sidecars), Pear Desktop at `~/skoop-backups/pear/<timestamp>/pear` (`roaming` / `local` scopes, each with the `YouTube Music` / `Pear Desktop` userData folders; Chromium caches and `lockfile` are skipped) and OpenCode at `~/skoop-backups/opencode/<timestamp>/opencode` (`config/`, `state/` without `service.json`/`locks`/`pty`, and `auth/` with the `opencode auth export` dump plus any legacy `auth.json` files). The registered repo list is also snapshotted to `~/skoop-backups/repos/<timestamp>/repos/repos.json` (`-NoRepos` skips it); `core/restore-backup.ps1 -Only repos` restores it to `%LOCALAPPDATA%\skoop\repos.json`, which `install.ps1` prefers over `manifests/repos.json` when cloning. `core/restore-backup.ps1` is a standalone, opt-in companion (used automatically for Vicinae, Pear Desktop, Firefox, Atuin, OpenCode, the SSH key and the repo list in the `tailscale` phase callback): it picks the newest timestamp for each app independently and merges them back, rather than expecting one coherent snapshot for all five. It never touches the remote host. Downloads use an `ssh`-to-`tar` stream with an `scp` fallback; Firefox cache folders are excluded because their deep paths exceed Windows' `MAX_PATH`, and ssh/scp pass `-o LogLevel=ERROR` so host-key notices can never be parsed as the remote home path. Only the `-Only` paths are probed for their newest timestamp (each probe is its own SSH round trip; the parallel per-app children would otherwise open seven connections each), and `-LogPath` names the per-run log — the parallel children receive `restore-<app>-<stamp>.log` so they never share a file. Downloads report progress every 2 s: `X MB (Y MB/s)` while transferring, plus a percentage once the tar size for that stamp is known — the size comes from `%LOCALAPPDATA%\skoop\restore\size-<app>-<stamp>.txt`, written after each successful download, never from a remote `du -sb` (that walks the whole profile first, delaying the transfer and thrashing a slow remote disk when the parallel children all do it). A `download: 100%` and `extract: starting/done` line close it out. Every ssh call uses `-n` plus `-o BatchMode=yes -o ServerAliveInterval=15 -o ServerAliveCountMax=3`: the four restore children are started with `-NoNewWindow` and share one console, and without `-n` their ssh processes contend over the console stdin handle and stall the session for a minute or more. Never assign `$script:LogPath` near the top of the script: in a script that *is* the `-LogPath` parameter, and clearing it silently falls back to a second-granularity default name that collides between processes. `-Only firefox|vicinae|atuin|pear|opencode|ssh|repos`, `-Stamp`, `-List`, `-DryRun`, `-NoBackup` and `-NoRestart` give control; Firefox must be closed (locked profile files), a running `vicinae-server` is stopped/restarted around the copy and a running Pear Desktop is stopped for its restore (a stale `lockfile` is removed). OpenCode's `auth/export.json` is imported with `opencode auth import` (the CLI must exist) and legacy `auth.json` files are copied back for older builds. Pear Desktop cookies are DPAPI-encrypted, so restoring under a different Windows user or on another machine may still require a Google sign-in; its app config/local storage are restored either way. Atuin is per-shell (no service to stop), but the restore deletes stale `*.db-wal` / `*.db-shm` first so a restored DB is not replayed against local journal data, and warns to close other Atuin shells; the Atuin archive contains the encryption key and command history, the Vicinae archive contains its database master key and the OpenCode archive contains exported credentials, so protect them. `Restore-Vicinae` writes `keychain/vicinae-master-key` back into Windows Credential Manager (generic credential `vicinae-master-key`, via `CredWriteW`) before the server restarts; snapshots without it leave the keychain alone and reset `data\vicinae.db*` / `clipboard.db*` when they are still SQLCipher-encrypted and no key exists (vicinae-server fatals on startup without it, so that history is lost rather than leaving a dead launcher). After restoring on a fresh machine, re-run `.\apps\vicinae\configure.ps1 -Restart` if the managed keybinds were changed outside the repo. `-NoVicinae` / `-NoAtuin` / `-NoPear` / `-NoOpenCode` skip those snapshots on the backup script. Firefox and Atuin are restored automatically through the Tailscale hook once per machine (markers `firefox-restore.done` / `atuin-restore.done`); `-ForceFirefoxRestore` / `-ForceAtuinRestore` repeat them and `-SkipFirefoxRestore` / `-SkipAtuinRestore` opt out. Atuin is only a file copy and does not need the app installed yet; Firefox is installed by Scoop before its early restore. Firefox is closed/relaunched around the copy and Atuin warns about other open shells.
