# AGENTS.md

Index of this repository for agents and humans. **skoop** is a declarative Windows
dev setup: [Scoop](https://scoop.sh) packages plus a repo-managed PowerShell profile,
restored from one manifest. There is no build system, no tests, and no package
manager of its own — the files are the product.

## Conventions

- **Add or remove a package** by editing `scoop.json`; keep the `{ "Info": "", "Source": ..., "Name": ... }` shape and keep apps grouped by source. Real-world workflow: `scoop install <app>` then `scoop export | Out-File -Encoding utf8 scoop.json` (verify the diff before committing).
- **Buckets must exist before their apps**; if you introduce a new bucket, add it to `buckets` and make sure `install.ps1`/`bootstrap.ps1` still import cleanly (buckets are git repos, hence the git step).
- The `kbots` app builds from a pinned `deploy/YYYY.MM.DD.n` source tag; `bun`, `rustup`, `mingw` and `git` are already in `scoop.json`. Its install does not start the daemon — run `kbots daemon start` after setup.
- **Scripts target Windows PowerShell 5.1+** with `$ErrorActionPreference = 'Stop'`, and must run without admin unless explicitly elevated. Avoid PowerShell 7-only syntax.
- **Idempotence matters.** `install.ps1`/`bootstrap.ps1` and `profile.ps1` may run repeatedly; check before appending to `$PROFILE` and guard optional commands with `Get-Command ... -ErrorAction SilentlyContinue`.
- **Interactive Herdr peer choice:** `.\install.ps1 -HerdrPeer` is a switch (no value) and always opens the gum peer picker; `-Peer <ip|name>` skips it, `-HerdrUser` presets the SSH user. Never commit a machine name or tailnet IP into tracked files — pass them at runtime (arguments or `SKOOP_HERDR_PEER` / `SKOOP_HERDR_USER` env vars for piped runs).
- **gum pickers:** gum draws its UI on **stderr** and writes only the answer to **stdout**. Do not capture it with `... 2>&1 | Out-String` (no terminal → gum draws nothing and returns no choice) and do not simply let PowerShell inherit stderr (PS 5.1 raises a terminating `NativeCommandError` for every UI frame under `$ErrorActionPreference='Stop'`). `Invoke-GumPicker` in `install.ps1` / `setup-herdr-ssh.ps1` starts gum via `System.Diagnostics.ProcessStartInfo` with `RedirectStandardOutput = $true` and `RedirectStandardError = $false`, then reads the answer from `StandardOutput`. `-NoGum` / `$env:SKOOP_NO_GUM=1` still forces the numbered prompt when a terminal cannot render gum at all.
- **PowerShell 7 preference:** `install.ps1` re-launches itself with `pwsh -NoProfile -File <script> <same args>` when it is running under Windows PowerShell 5.1 and `pwsh` is already on PATH, because 5.1 mangles native stderr and BOM-less UTF-8. `-NoPwsh` / `$env:SKOOP_NO_PWSH=1` opts out; piped `irm ... | iex` runs (no `$PSCommandPath`) and `bootstrap.ps1` keep running in the invoking shell. Keep scripts 5.1-compatible — the re-launch is an optimisation, not a requirement.
- **Keep the three docs in sync** when behavior changes: `README.md` (users), `AGENTS.md` (inventory/conventions), and the comment-based help in `install.ps1`.
- **Verify changes** with `scoop export` (manifest fidelity) and by re-running the affected script in a fresh `powershell` process; there is no automated test suite.
- **Editor config:** keep Zed user config in `zed/` and re-run `.\configure-zed.ps1` after edits. Never put credentials, API keys or tokens in these public JSON files.

## Git workflow

- **Auto commit and push.** After finishing a change, commit and push it to `origin`
  without waiting to be asked. Stage only the files you touched (`git add <paths>`),
  write a concise imperative message (e.g. `Add one-shot install script and README`),
  then `git push`. Don't sweep unrelated work-in-progress into the commit; if the push
  is rejected, `git pull --rebase` and retry once.
- Skip the commit/push only when the user explicitly asks you not to, or when the change
  is unverified and the user wants to review it first.

## Notes

- This repo is not itself a Scoop bucket and publishes no manifests; it adds the `kbots` bucket from `https://github.com/KeiosStarqua/kbots` in `scoop.json`. `install.ps1` is fetched raw from `https://raw.githubusercontent.com/KeiosStarqua/skoopub/main/install.ps1` (override with `-RepoRawBase`).
- Tailscale installs its service separately; the Scoop package provides the CLI (`tailscale`, `tailscaled`) and needs `tailscaled` running before `tailscale status` works. Both bootstraps now start the Windows `Tailscale` service (and set it to Automatic) when present, otherwise launch the Scoop `tailscaled` shim; sign-in stays interactive (tray icon or `tailscale up`). The Windows CLI may be missing from PATH (the official installer does not add it) or unable to talk to the daemon while Tailscale itself works. Both bootstraps probe it with `tailscale status` and print sign-in advice without failing; `setup-herdr-ssh.ps1` resolves `tailscale.exe` from PATH, Program Files and Scoop, and if it still cannot list peers, asks for the machine's Tailscale IP / MagicDNS name (`-Peer` supplies it non-interactively). Peer listing is the only CLI-dependent step; never make the network setup itself depend on the CLI.
- `zeldrisho/scoop-bucket` is third-party: the UniKey manifest installs the official `unikey.org` archive with a pinned SHA-256 hash. Verify the diff when bumping versions.
- `hoilc/scoop-lemon` is third-party and supplies `cava` (Scoop's `extras` bucket has no cava manifest). Its manifest installs the official `karlstav/cava` Windows MSI with a pinned SHA-256 hash; verify the diff when bumping versions. Add it to `scoop.json` buckets before the app, like any other bucket.
- Public PCs may already have UniKey installed outside Scoop. Both bootstraps detect it (running `UniKeyNT`, uninstall registry, existing Scoop app dir) and import a temporary manifest without `unikey`; `-ForceUniKey` overrides.
- Rust: `rustup` installs the toolchain into `persist\rustup`; the bootstraps only set GNU as default when `rustup show active-toolchain` fails, so an existing MSVC choice survives. Cargo's bin is on the user PATH via the Scoop manifest. A fresh `rustup` writes "no active toolchain" to stderr and exits 1; under `$ErrorActionPreference = 'Stop'` that is a terminating `NativeCommandError` in PowerShell 5.1, so both scripts run the check via `cmd /c ... 2>&1` and inspect `$LASTEXITCODE` instead.
- Firefox: the bootstraps call `firefox --setDefaultBrowser` after installing it (skipped when http is already handled by Firefox). Direct `UserChoice` registry writes are blocked on modern Windows, and Windows 11 may open Settings for confirmation; failures are non-fatal.
- Firefox extensions: `firefox-policies.template.json` is copied to `<scoop>\apps\firefox\current\distribution\policies.json` (Scoop persists that folder) and auto-installs Bitwarden and "I still don't care about cookies" (both AMO) plus mymind (pinned vendor XPI URL) with `normal_installed`. It also sets `DisplayBookmarksToolbar: always`, a `skoopub` managed-bookmarks folder (Hacker News, mymind, Scoop, OpenCode, YouTube to Transcript), and `Homepage` (ChatGPT as URL with `StartPage: homepage`). It disables the built-in password-saving prompt via `OfferToSaveLogins: false` plus `OfferToSaveLoginsDefault: false` (Bitwarden handles logins). Firefox reads policies at startup, so restart it after the first setup; switch to `force_installed` only if an extension should be locked.
- GitHub auth: `gh auth login` alone does not configure git. `setup-gh-auth.ps1` runs `gh auth setup-git`, which writes `credential.https://github.com.helper` (`gh auth git-credential`) so `git push` uses the gh token via HTTPS. Both bootstraps call it after the ShareX fix; `-SkipGhLogin` makes that step non-interactive, and failures are non-fatal.
- Herdr remote: `setup-herdr-ssh.ps1` uses Tailscale SSH, so no key pair, password or `~/.ssh/config` edit is needed. The target machine must have Tailscale SSH enabled (`tailscale set --ssh=true`) and the tailnet SSH policy must permit the login; a rejection names the user that was tried, which `-User` can override. The script probes users without prompting and saves the machine with `herdr machine add <user>@<machine> --label <machine>`: Herdr prepares the remote server and keeps the profile, so it shows up in the sidebar of every open client. Nothing is started with `herdr --remote`, and an already-saved target is left untouched (`herdr machine list` is checked first because `machine add` would otherwise create a duplicate profile), so running `install.ps1` → "Connect Herdr only" from inside a pane is safe. Never put a machine name or tailnet IP in tracked files; peer addresses come only from `tailscale status` or the runtime prompt.
- Zed's in-app auto-update is disabled in `zed/settings.json` (`auto_update: false`); otherwise it installs outside Scoop and the pinned version in `scoop.json` stops matching reality. `innounp` is pulled in automatically as the installer dependency.
- Zed config lives in `%APPDATA%\Zed` (`settings.json`, `keymap.json`, `tasks.json`, `themes/`, `snippets/`); extensions install into `%LOCALAPPDATA%\Zed\extensions`. `configure-zed.ps1` is called by both bootstraps after gh auth and copies `zed/*.json` there with timestamped backups before overwriting (`-NoBackup` skips that). Piped installs fetch `zed/*.json` to `%LOCALAPPDATA%\skoop\zed`.
- Zed extensions: `auto_install_extensions` declares PowerShell, HTML, Dockerfile, Docker Compose, TOML, Nix and SQL; Zed installs them at startup. The PowerShell extension needs `pwsh` (now in `scoop.json`); Rust needs no extension because Zed ships `rust-analyzer` natively, so `lsp.rust-analyzer` is configured instead of a nonexistent `rust` extension ID.
- Rio config: `rio/config.toml` sets `[fonts] size = 16`; Rio has no separate zoom setting, so this is the zoom level. `configure-rio.ps1` copies it to `%LOCALAPPDATA%\rio\config.toml` with a timestamped backup of a changed original unless `-NoBackup`, and Rio hot-reloads the file without a restart. Both bootstraps call it after the Zed config; piped installs fetch `rio/config.toml` and `configure-rio.ps1` to `%LOCALAPPDATA%\skoop`.
- Git identity: `setup-git-identity.ps1` writes `user.name = Keios` and `user.email = git@taquangkhoi.com` to the global git config so all commits are attributed correctly. `-Local` targets the current repository and `-Name` / `-Email` override the defaults; the script is idempotent and called by both bootstraps after gh auth.
- Komorebi hotkeys / padding / workspace rules: `komorebi/whkdrc` and `komorebi/komorebi.json` are deployed to `%USERPROFILE%\.config` with timestamped backups of changed originals unless `-NoBackup`. The JSON sets tight gaps (`default_workspace_padding: 4`, `default_container_padding: 2`) instead of Komorebi's 10px defaults, uses `Columns` on the Terminal workspace, and names nine workspaces with `initial_workspace_rules` (assign on first appearance; manual moves still allowed): Firefox + Rio on workspace 0 (`Win+1`), Zed + VS Code + Pear Desktop ("YouTube Music.exe") on workspace 1 (`Win+2`), Chrome on 2, Discord/Telegram on 3, Explorer on 4, Spotify/VLC on 5, 6–8 spare. Rules are loaded into Komorebi's global state; already-open windows are not moved, so relaunch an app or use `komorebic enforce-workspace-rules` if you want existing windows rearranged. `komorebic replace-configuration` applies the config to an already-running daemon, and `komorebic start -c` uses it on a fresh start. Komorebi cannot pin an app to a column declaratively, so `komorebi/pin-terminal-layout.ps1` polls the state and reorders the Terminal columns to keep Rio left / Firefox right; it is started hidden and added to Startup by `configure-komorebi.ps1` unless `-NoPin` (`-RestartPin` relaunches it). `configure-komorebi.ps1` starts Komorebi when needed and starts/reloads `whkd`; `-NoStart` only deploys and `-Restart` forces a reload. The scheme uses `Win` as the primary modifier (Hyprland-style): `Win+Arrow` focus, `Win+Shift+Arrow` move, `Win+Ctrl+Arrow` resize, `Win+1..9` workspaces. H/J/K/L are avoided because Windows 11 reserves `Win+H/J/K/L`; Firefox is `Win+Shift+W` (not `Win+Shift+B`, which resets the graphics driver). `Win+Arrow` may still be captured by Snap layouts. whkd uses `.shell powershell` so it does not depend on `pwsh` being on PATH.
- YASB config: `yasb/` is vendored from SleepyCatHey/Ultimate-Win11-Setup (YASB config for Komorebi). `configure-yasb.ps1` copies `config.yaml` and `styles.css` to `%USERPROFILE%\.config\yasb` with timestamped backups unless `-NoBackup`, creates `.env` from `.env.example` when missing, and starts YASB (`-Restart` forces a restart). Weather uses `YASB_WEATHER_API_KEY` / `YASB_WEATHER_LOCATION` from `.env`, wallpapers use `YASB_WALLPAPER_DIR`; never commit real credentials. In-app updates are off (`update_check: false`) so Scoop owns the version, and the cava widget uses the `cava` app from the `lemon` bucket in `scoop.json`.
- Nushell shortcut: `profile.ps1` defines `n` → `nu` only when Nushell is installed and no `n` alias already exists. `setup-nushell.ps1` writes `%LOCALAPPDATA%\skoop\nu-autostart.cmd` containing `doskey n=nu $*` and appends it to HKCU `Command Processor\AutoRun` only if absent, preserving existing entries; `-Remove` undoes both. This is an alias, not a shell replacement — PowerShell/cmd still start normally.
- Starship prompt: `starship/starship.toml` is the repo copy; `configure-starship.ps1` deploys it to `%USERPROFILE%\.config\starship.toml` (Starship's default path, so no `STARSHIP_CONFIG`). PowerShell loads it from `profile.ps1` (`starship init powershell`, skipped when `starship` is missing or `(Get-Command prompt).Source` is already `starship`). cmd.exe has no prompt hook of its own, so it needs Clink (in `scoop.json`): the script writes `%LOCALAPPDATA%\clink\starship.lua` with the documented `load(io.popen('starship init cmd'):read('*a'))()` line and runs `clink autorun install`. Clink appends its command to cmd's AutoRun value, so the Nushell doskey entry survives; the script re-checks AutoRun and warns if it vanished. Both files are written as UTF-8 **without BOM** — PowerShell 5.1's `Get-Content -Raw` default decodes BOM-less files as ANSI (mojibake glyphs) and `Set-Content -Encoding UTF8` adds a BOM, which Starship's TOML parser and Clink's Lua loader reject, so the script uses `[System.IO.File]::ReadAllText/WriteAllText` with explicit UTF-8. `-NoCmd` / `-NoAutorun` opt out; Clink absent just prints a hint.
- Vicinae shortcut: `vicinae/keybinds.json` sets `global_shortcuts.toggle` to `control+space`. `configure-vicinae.ps1` copies it into `%LOCALAPPDATA%\vicinae\config` and adds `"./keybinds.json"` to `settings.json`'s `imports`, so GUI edits never overwrite it. Vicinae reads global shortcuts at server start, so re-run with `-Restart` after changing the binding.
- Vicinae: the global shortcut only works while `vicinae-server.exe` is running. Scoop ships the server and a Start Menu shortcut but no login autostart, so `enable-vicinae-autostart.ps1` creates a per-user Startup `.lnk` targeting `apps\vicinae\current\bin\vicinae-server.exe` and starts it immediately. It is idempotent (repairs shortcuts pointing at versioned folders), non-fatal in both bootstraps, and `-Remove` / `-NoLaunch` give an opt-out. Because the installer may run inside a Herdr pane, the script clears `HERDR_ENV`/`HERDR_PANE_ID`/etc. before starting the server; otherwise every terminal launched from Vicinae inherits them and `herdr` refuses to start with the "nested herdr"/inception message. Use `-Restart` on an existing contaminated server.
